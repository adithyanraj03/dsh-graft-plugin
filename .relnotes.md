# dsh-graft-plugin v0.1.1

Fixes a client-mounting bug in 0.1.0: the browser bundle registered itself with `window.__ModuleLoader__.load({ id: "graft-status" })` — the cordis row handle — but the client loader keys modules by the **package name** and `arrive()` asserts `factories.has("dsh-graft-plugin")`. The factory landed under the wrong key, so the assert fired on boot and the client half (composer chip + viz tab) never mounted.

- `src/client.js` now registers under `dsh-graft-plugin`. The row id `graft-status` is untouched everywhere it belongs (storage keys, prompt section, effect labels).
- The test suite carries a source-level regression guard for the module key (two new checks; 93 total).

Asset note: this release's tarball is attached under the stable name `plugin.tgz`, so the marketplace entry's `tarball:` key can point at `releases/latest/download/plugin.tgz` and stay valid across versions.
